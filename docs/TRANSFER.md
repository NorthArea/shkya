# Перенос проекта на другой компьютер

## Развернуть из Git

На новом компьютере нужны Git, Python 3, `make` и Godot версии, указанной в `tools/godot.sh`. Для инструмента резервной копии ниже нужен Python 3.10+. Доступ к приватному репозиторию настройте отдельно: авторизация не хранится в Git. При настроенном SSH можно использовать `git@github.com:NorthArea/shkya.git`.

```sh
git clone https://github.com/NorthArea/shkya.git
cd shkya
git log -1 --oneline
git status --short
./tools/godot.sh --headless --version
make test-headless
```

Установите Godot до вызова launcher: он ищет `tools/local/Godot.app`, команды `godot`/`godot4` и `/Applications/Godot.app`. Для другого расположения задайте `GODOT_BIN` на нужную команду:

```sh
GODOT_BIN=/path/to/Godot make test-headless
```

`tools/local` не хранится в Git; локальная ссылка на движок со старого компьютера не нужна при установленном системном Godot. Игровые ресурсы входят в Git. Godot создаст `.godot` при импорте; каталоги `builds` создают инструменты проверок. Результаты прошлых проверок из `builds` и настройки пользователя переносятся отдельно.

`make test-headless` явно пропускает графические наборы. Проверка FPS и визуального качества на новом компьютере требует новых замеров; старые результаты сохраняют сведения об исходном Mac.

## Развернуть без GitHub из подготовленного bundle

Можно перенести и распаковать `shkya-git-transfer.zip` либо скопировать `final-history.bundle`, `final-history.bundle.sha256` и `FINAL_HEAD.txt` из пакета `builds/transfer/2026-11-04/`. В bundle входят полная Git-история, основная ветка и все архивные теги с изолированными работами.

Из каталога с этими файлами:

```sh
shasum -a 256 -c final-history.bundle.sha256
git clone --branch main final-history.bundle shkya
cd shkya
git fsck --full
git rev-parse HEAD
cat ../FINAL_HEAD.txt
git remote set-url origin git@github.com:NorthArea/shkya.git
```

Два выведенных SHA должны совпасть. После установки Godot запускайте `make run`. Bundle не содержит кэш импорта: первый запуск создаст его штатным launcher. Новая рабочая копия будет чистой; очередь и ограничения проверок — `docs/workflow/backlog.md`, исходные поручения — `docs/requests/OWNER_MESSAGES.md`.

Когда GitHub восстановит доступ, выполните `git fetch origin`, затем `git push origin main` без force. Если на сервере появились новые коммиты, сначала сопоставьте истории и сохраните обе стороны. После push сравните `git rev-parse HEAD` с `git ls-remote origin refs/heads/main`; несовпадение оставляет передачу через GitHub незавершённой.

## Дополнительная полная копия

Полный архив нужен для сохранения локальных доказательств проверок, программ из `tools/local`, ignored-файлов и незакоммиченного состояния. Он дополняет развёртывание из Git.

## Создать копию

Нужны Python 3.10+ и Git. На время упаковки завершите запись в проект: остановите свои проверки и игру, сохраните файлы и не меняйте Git. Скрипт проверяет изменения файлов и при обнаружении оставляет незавершённый `.partial`, завершаясь с ошибкой. Он не останавливает приложения сам.

Из корня проекта:

```sh
mkdir -p /private/tmp/shkya-transfer-20261104
python3 tools/prepare_transfer.py /private/tmp/shkya-transfer-20261104/repository.tar.gz
python3 tools/prepare_transfer.py --verify /private/tmp/shkya-transfer-20261104/repository.tar.gz
```

Выберите новое имя каталога, если такой архив уже существует. Назначение должно быть вне проекта; можно указать подключённый внешний диск. Скрипт не перезаписывает существующие архивы и не удаляет исходники. `/private/tmp` подходит для временной подготовки: готовую копию перенесите на постоянный носитель.

Используется gzip уровня 1; каждые 512 МиБ скрипт печатает прогресс. До запуска проверьте свободное место через `df -h .`. Исходное дерево занимает около 30 ГиБ; размер сжатой копии заранее неизвестен. Нужен запас под архив, а при пробном восстановлении — ещё под распакованный проект. После ошибки `.partial` остаётся для разбора; повторный запуск требует другого имени.

В архив входят:

- `.git` целиком: история, локальные ветки, stash, reflog, индекс и настройки репозитория;
- tracked, untracked и ignored-файлы, включая `assets/local`, `tools/local`, `builds`, локальные конфиги и `.godot`;
- встроенный перечень файлов с SHA-256 и сведения о состоянии Git на момент старта.

`.godot` сохранён, потому что замороженные сцены проверок в `builds` ссылаются на его импортированные ресурсы. Абсолютные ссылки внутри проекта превращаются в относительные ссылки в архиве. Исходные ссылки на диске не меняются.

На исходном Mac `tools/local/Godot.app` ссылается на приложение вне проекта. Скрипт кладёт содержимое этого приложения непосредственно по пути `tools/local/Godot.app` в архиве. Другие внешние ссылки приводят к отказу, чтобы зависимость не потерялась молча. Репозитории с внешним Git object store (`alternates`) и linked worktree вместо собственного `.git` также не принимаются.

Команда `--verify` сначала сверяет SHA-256 архива с соседним `.sha256`, затем читает весь gzip/tar и сверяет каждый файл со встроенным перечнем. Проверка ничего не распаковывает. Архив может содержать локальные токены из ignored-конфигов: храните и переносите его как личную резервную копию.

## Восстановить

Скопируйте каталог с архивом и `.sha256` на новый компьютер. До распаковки, находясь рядом с архивом, проверьте контрольную сумму:

```sh
shasum -a 256 -c repository.tar.gz.sha256
mkdir restored
cd restored
tar -xzf ../repository.tar.gz
cd shkya
python3 tools/prepare_transfer.py --verify ../../repository.tar.gz
git fsck --full
git status --short
git branch --all
git stash list
```

Распаковывайте в новый пустой каталог, чтобы не смешать две рабочие копии. В корне `restored` также появится `__transfer_manifest__.json` со списком файлов и исходным состоянием Git. Сравните `head`, `status`, `refs` и `stash` из поля `git` с восстановленным репозиторием. Полный `.git` позволяет восстановить и незакоммиченное состояние, и работу, ещё не отправленную на сервер.

На совместимом Mac проверьте локальный движок через штатный launcher:

```sh
./tools/godot.sh --headless --version
make test-headless
```

`make test-headless` пропускает графические наборы и не подтверждает FPS или визуальное качество. Новый компьютер требует новых замеров. Для другой ОС/архитектуры установите совместимый Godot версии, указанной в `tools/godot.sh`; macOS `.app` на ней не запустится. Launcher принимает `GODOT_BIN` и умеет искать системный Godot.

## Что лежит вне рабочего каталога

Эти данные архив проекта не захватывает. Переносите нужное отдельно средствами соответствующих приложений; секреты в Git не добавляйте:

- личные инструкции, навыки и история агента: `~/.codex`, `~/.agents`, `~/.paiw`, а также настройки используемых редакторов;
- SSH-ключи, `~/.gitconfig`, credential helper, macOS Keychain, VPN и авторизации MCP;
- пользовательские сохранения и настройки Godot: на macOS обычно `~/Library/Application Support/Godot/app_userdata/ШКЯ: Ничего необычного`;
- внешние рабочие копии, временные клоны и ветки в других репозиториях: их `.git` не входит в основной проект;
- переменные окружения и программы, установленные вне `tools/local`.

Перед отказом от старого компьютера проверьте, что нужные внешние рабочие копии и пользовательские данные тоже перенесены. Наличие имени временного каталога в старом backlog не доказывает наличие его содержимого в текущем репозитории.
