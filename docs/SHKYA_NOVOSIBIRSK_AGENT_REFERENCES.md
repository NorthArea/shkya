# SHKYA: Novosibirsk — references for the Godot implementation agent

**Проверено:** 27 октября 2026 (Asia/Almaty). **Назначение:** единственный набор внешних и внутренних референсов для реализации демо-миссии «За хлебом».

## 0. Порядок приоритета: читать именно так

1. **Источник истины о задаче:** `DEMO_TASK.md` из архива [SHKYA_NOVOSIBIRSK_DEMO.zip](https://chatgpt.com/library?file_id=libfile_94511fe3ea808191995751c4275753cc&account_id=personal). Содержит границы MVP, механику, состояния квеста и критерии приёмки.
2. **Источник истины о композиции:** десять последовательных `01_*.png` … `10_*.png` из того же архива. Это скриншоты *предполагаемого геймплея*, а не готовые текстуры и не точная карта города.
3. **Источник истины о персонажах:** мультфильмы Евы Морозовой, ссылки ниже. Оригинальные черты лица, пропорции и характер важнее геометрии концептов.
4. **Референс геймплейного ощущения:** *The Simpsons: Hit & Run* и открытая Three.js-реконструкция. Переносить нужные **идеи и авторскую MIT-логику**, не переносить оригинальные игровые ассеты.
5. **Техническая документация:** официальные страницы Godot. Если пример противоречит текущей версии Godot, брать API именно выбранной версии движка.

> **Неприкосновенные ограничения:** один герой — Илюша; Бабка и продавщица — единственные интерактивные NPC; одна белая Lada; снег; мрачный серый и грязный Новосибирск с жёлтыми фонарями; одна миссия; жёлтый `!` на выдачу и `?` на сдачу. У Илюши **всегда пустые руки** — хлеб хранится только как флаг `has_bread` и иконка UI. Зимняя одежда Илюши: ярко-лаймовый пуховик с белым воротником, длинные тёмно-зелёные брюки, зимние ботинки. Жёлтый завиток волос остаётся виден.

Для проверки логики использовать **пути внутри репозитория после клонирования**; точные API и расположение файлов могут измениться между коммитами.

| Приоритет | Файл / система | Что использовать |
| --- | --- | --- |
| P0 | `src/player-movement.ts` | Алгоритм ускорения, замедления, поворота персонажа относительно камеры. |
| P0 | `src/vehicle-physics.ts` | Идея аркадного управления, реакция на газ/тормоз/руль; для демо реализовать упрощённую версию средствами Godot. |

**Техническое решение для первого прохода:** один `CharacterBody3D` под Илюшу, отдельный простой контроллер машины, `SpringArm3D + Camera3D`, два `Area3D` NPC, одна компактная `QuestStateMachine`, один `CanvasLayer` для UI. Не начинать с физики четырёх колёс, AI-трафика, процедурного города или большой системы инвентаря.

## 6. Что агенту запрещено считать обязательным

- Старые варианты сценария с очередью у киоска, погоней, талонами, дополнительными NPC и вручением 3D-батона — **исключены**.
- Старый летний костюм Илюши (поло, шорты, тапочки) — **исключён для зимней версии**.
- Полную копию мира, транспорта, уровня розыска или полицейских механик из *Hit & Run* — **не делать**.
- Не подменять персонажей из ШКЯ генерическими похожими мультфигурами.
- Не использовать без разрешения чужие звуковые дорожки, спрайты или модели из сериалов и игр.
- Не добавлять механики, которых нет в `DEMO_TASK.md`, без отдельного решения владельца проекта.

## 7. Рекомендуемая процедура работы агента

1. Распаковать [архив концептов и ТЗ](https://chatgpt.com/library?file_id=libfile_94511fe3ea808191995751c4275753cc&account_id=personal), прочитать `DEMO_TASK.md`, просмотреть все 10 кадров подряд.
2. Посмотреть V01/V02/**V04**, описать «паспорт» Илюши и Бабки (силуэт, голова, цвета, одежда) и зафиксировать, что полезного в V04, прежде чем генерировать/рисовать игровые ассеты.
3. Ознакомиться с G01/G02/G03: замерить темп базового управления; не переносить лишний функционал.
4. Реализовать **серый играбельный blockout** полностью, от первого диалога до завершения квеста, по T01–T06.
5. Только после успешного полного прохождения заменить blockout визуальными ассетами, освещением и персонажами по V01/V02/C01/C02 и кадрам 01–10.
6. Прогнать приёмочные сценарии из `DEMO_TASK.md`; зафиксировать расхождения с референсами и не расширять MVP без согласования.

**Статус прав:** частный демонстрационный прототип для потенциального соглашения с правообладателями ШКЯ. Использование оригинальных охраняемых персонажей в публичном или коммерческом проекте должно быть согласовано отдельно; наличие референсов не предоставляет лицензию.
