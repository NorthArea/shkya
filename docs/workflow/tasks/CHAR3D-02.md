# CHAR3D-02 — Все персонажи в 3D (вариант A по умолчанию)

Решение владельца 29.10.2026 (день): после прототипа CHAR3D-01 — «давай всех в 3D». Результат: каждый персонаж игры (Илюша, Бабка, продавщица, полицейский, «военком», росгвардеец ART-08, все 14 силуэтов жителей из `Residents.SILHOUETTES`: babka, woman, man, boy, shuba, beret, violet, ushanka, ushanka_walk, tourist, kid, kid2, dog, kolpak, bow, turban — по факту списка) строится `CharacterBody3DLook` по паспорту из своих SVG; `LOOK_3D` по умолчанию `true` в `npc.gd` и `ilyusha.gd`, спрайт — запасной путь (`--sprites` или константа), портреты диалога — SVG как были. Сбитый житель (KNOCK-01) в 3D кувыркается объёмом. Критерий — похожесть на арт с игровой камеры (метод LOOK-01/ART-07: кадры из игры, не листы).

Владелец: root; исполнитель — агент. Зависимости: CHAR3D-01 (коммит 7514774), KNOCK-01 (b18903f), ART-08 (росгвардеец, идёт параллельно — его SVG и правки `generate_characters.py` подхватить в конце перегенерацией паспортов).

## Объём

1. **Паспорта для всех** — `tools/character_passports.py`: поддержка всех функций генератора (`vendor`, `officer`, `guard`, `resident_*`), детали каждого (платок, чалма, бант, колпак, собака на поводке, санки, банка, пакеты, портфель/планшет «военкома», бронежилет и берет росгвардейца, шапки пацанов); `passports.json` со всеми персонажами; у кого детали не выделяются автоматически — явные описания в скрипте (таблица деталей по персонажу), не «пропустить».
2. **Облики** — `character_body3d.gd`: новые типы деталей по потребности (поводок + собака как отдельная фигурка-лофт, санки — коробка с полозьями, банка — цилиндр, планшет — пластина); исправить слабые места прототипа: нос Илюши в фас (стереть нарисованный хобот с фасовой деколи в области носа и доверить объёму; проверить, что в 3/4 хобот один), лацканы/галстук/погоны полицейского и «военкома» как швы или накладки, рисованные детали тела (карманы, пуговицы, стёжка) хотя бы как швы шейдера для всех; повязка полицейского на плече, а не у локтя; двоение черт на стыке проекций — сузить полосу смешивания/маску деколи.
3. **Движение** — ходьба для всех (маятник по пройденному пути), поворот к собеседнику, дыхание как у NPC; **полёт KNOCK-01 в 3D**: кувырок объёмом вокруг поперечной оси (ветка в `resident.gd` уже есть — проверить кадром и доработать: руки/ноги в полёте разведены), лёжа — на боку/спине, встаёт — через присед; снежинки, пыль, тень как у спрайта.
4. **Переключатель по умолчанию** — `LOOK_3D := true`; аргумент `--sprites` возвращает спрайты (для сверок и как запасной путь); `--look3d` оставить как no-op для совместимости скриптов.
5. **Тесты** — `tests/char3d_test.gd` расширить на всех персонажей (строится, рост ±5 %, контур, ходьба, паспорт); все наборы `make test` при `LOOK_3D = true` — 0 failures (ART01 и сверки спрайтов, если они смотрят на `CharacterSprite`, перевести на проверку выбранного облика или запускать с `--sprites` — решить и записать); FPS `make fps` ≥ 100 в среднем с полным городом в 3D (14 жителей + патрули + Бабка + продавщица + Илюша), иначе — кэш мешей/материалов на персонажа, одна отрисовка контура на фигуру (объединить hull в один меш) или уменьшить число деталей на дальних.
6. **Кадры** — `builds/screenshots/CHAR3D-02/`: каждый персонаж «спрайт | 3D» с игровой камеры 3 и 6 м (фас, 3/4), общие кадры: двор с Бабкой, киоск с постами, тротуар B с жителями, полёт сбитого жителя в 3D (4 фазы), диалог с Бабкой и продавщицей. Независимая сверка по кадрам «похож / в стиле ШКЯ» — субагент-ревьюер без выводов исполнителя.

## Проверка

`make test` 0 failures с 3D по умолчанию; `make fps` ≥ 100; кадры и вердикт ревьюера; владелец играет `make run` и смотрит. Карточка CHAR3D-01 остаётся историей прототипа.
