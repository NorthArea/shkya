# CHARACTER-01 — персонажные механики по принципам Hit & Run

Статус — [backlog](../backlog.md), решения — [DECISIONS](../../DECISIONS.md), поручение MSG-0141.

- **Результат:** карта первичных персонажных механизмов SHAR, их нынешних аналогов/пробелов у героя и остальных, затем проверенные ограниченные сквозные изменения. «Вся механика» не означает обещание буквального набора неизвестных функций оригинала без source audit.
- **Владение:** root — композиция/контракты/интеграция; native_warning_triage — завершённый независимый read-only source audit. CHARACTER-02/03 получили принятые root API и разрешение только на новые helpers/developer tests; controller integration — после стабильной QA LOCOMOTION/IP.
- **Первичный срез:** native_warning_triage сверил C++ [3UR @c84f9ff9ae9b27a5d34dca7985ac819e70f62bc6](https://github.com/3UR/Simpsons-Hit-Run/tree/c84f9ff9ae9b27a5d34dca7985ac819e70f62bc6); таблица ниже фиксирует доказанные принципы и текущие пробелы, а не приёмку runtime.
- **Источники:** C++ 3UR/Simpsons-Hit-Run, действующие решения и C3–C8; PLAY-04 — принятый baseline сравнения. Локальные анализы переиспользовать после проверки их источника; код, текстуры, модели, скелеты и анимации реализуются своими средствами.
- **Участники:** Ilyusha/CharacterBody3D, CharacterSprite/UniformVisual/Skeleton3D, NPC/Residents/Life, knock/состояния, вход/выход из машины, C3-взаимодействия и C7-укрытия/патрули. Связанные владельцы состояния сохраняются; новых ролей, миссий и населения поручение само по себе не добавляет.
- **Полномочия:** MSG-0141 разрешает целевые обоснованные изменения персонажного движения/прыжка/поворота/состояний/реакций/AI. Прежний технический PASS не запрещает новый контракт и не принимает новую реализацию. Камера, автомобиль, сенсоры/стелс, миссии/экономика и реальные маршруты сохраняют действующие гарантии.
- **Порядок:** первичная матрица → согласованные контракты/независимые критерии CHARACTER-02…06 → реализация/реальная композиция → независимые проверки. [LOCOMOTION-01](LOCOMOTION-01.md) — первый срез; не включённые в него темы остаются здесь открытыми до собственной задачи/обоснованного вывода.
- **Связь с обликом:** [IP-01](IP-01.md) возвращает нашего утверждённого 2D-Илюшу в 3D; автор механики не переизобретает лицо/одежду. Изменение rig согласовать до зависимой реализации; чужие модели и анимации не переносить.
- **QA:** ожидания выводятся из источника и выбранного контракта независимо; реальные Main/player/NPC, границы состояний/паузы/сброса, движение/прыжок/коллизии/укрытия/посадка/knock, личные маршруты и миссия. Изменения оракулов имеют отдельное основание, сохранённые исходные отказы и независимый review.
- **Evidence/приёмка:** `builds/checks/CHARACTER-01/`, детали ограниченных работ — их карточки. Полноту подтверждает проверенная матрица всего заявленного блока; одна удачная походка её не закрывает. Только headless/Dummy; GPU/FPS/ощущения/ручная игра NOT_RUN до разрешённых проверок, канонические запреты сохраняются.
