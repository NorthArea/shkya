# IP-01 — утверждённый Илюша №4: новая модель и скелетная анимация

Статус — [backlog](../backlog.md), решения — [DECISIONS](../../DECISIONS.md).

Приоритет №2 по MSG-0187–0188/0192: игровой герой требуется «1 в 1» как выбранный №4 и с нормальной анимацией движения; действующее решение — [DECISIONS](../../DECISIONS.md), строка «Персонажи: облик». Файл эталона существует и открыт по абсолютному пути 03.11; ошибка чтения относительного пути в сообщении не означает утраты изображения.

- **Результат:** в самой игре персонаж соответствует «1 в 1» [утверждённому №4](../../art/explorations/ilyusha/2026-11-02-independent-3d/04.png); правильные колени/локти и плавное движение. Показанная процедурная модель отвергнута MSG-0166 и не дорабатывается как финальный герой.
- **Назначение:** новый полноценный asset pipeline Blender → GLB → humanoid retarget → AnimationPlayer/AnimationTree → действующие Player/Lada consumers; существующий геймплей и фиксированный рост сохранить.
- **Владение:** blender_hero_sculpt — tools/art/build_ilyusha_blender.py и assets/models/characters/ilyusha; humanoid_animation_reference — проверенный источник клипов/rig; imported_hero_integration — imported adapter/Uniform facade/CharacterSprite guards/import resources/CC0 animation assets; root — интеграция/документы; независимый hero_concept_likeness_qa — сходство.
- **Инструмент:** существующая tools/local/Blender.app разрешена MSG-0169; её судьба после задачи. Blender работает в фоне/CPU без UI, звук и GPU-рендер не требуются. Новые установки не поручены.
- **Mesh:** связная деформируемая топология плеч/локтей/таза/коленей, поддерживающие петли и веса; прямой фас/профиль/спина/3/4 соответствуют эталону. Набор пересекающихся закрытых блоков модель не заменяет. Скульптор проверяет нейтральную позу и сгибы, независимый reviewer сравнивает форму с изображением.
- **Rig/источник:** Quaternius Universal Animation Library Standard, CC0, официальный https://quaternius.com/packs/universalanimationlibrary.html; только анимации, внешний персонаж не используется. Проверенные hierarchy/rest/clip provenance — локальный tools/local/references/animation; лицензия активных ассетов — assets/README.md.
- **Контракт:** один действующий GLB mesh/skin героя; настоящий thigh→calf→foot→ball. Target A-rest и source T-rest согласуются через официальный BoneMap/SkeletonProfileHumanoid/rest fixing; перенос одних имён/неисправленных quaternions запрещён. Scale/limb positions не берутся из чужих клипов; in-place root не управляет Player transform.
- **Потребители:** все UniformVisual.configure("ilyusha") идут в один imported adapter; CharacterSprite сохраняет public facade, NPC используют прежний pipeline. Imported AnimationTree не перезаписывается BonePoseBuffer; hide/teleport/reset/LOD/XRay и сесть/встать/реальные hand targets сохраняются.
- **Анимационный контракт:** фазовая адаптация к длинам ног с единым clock и world-lock всей стопы (позиция + ориентация). Старые ограничения переноса 7см/полёта 0.10с относились к отвергнутому low-step solver; для нового бега — заранее закреплённые plant/swing окна и геометрическая кривая. Сохранить head/hips bob≤3см, floor≤12мм, реальный rendered plant-slip≤0.8м/с и неизменность physics root/scale/длин. Raw counterfactual physics-skin сохранять как диагностику, не путать с render-sampled позой.
- **Приёмка:** сходство изображения и реального mesh; деформация коленей/локтей, нет разрывов; настоящие standing/seat bounds одного роста, no shrink/neck shortening; реальные foot floor/slip/lift/body bob и переходы; collision/камера/маршруты не меняются. Imported Skin named binds и indexed meshes измерять корректно.
- **Проверки:** адресный GLB/import/animation test и настоящая цепочка Player/Driver; действительные поведенческие пределы переиспользовать, obsolete author14/runtime16 детали не принимать за новый стандарт. Godot — launcher headless/Dummy, GPU/FPS и игровое ощущение не выдавать за PASS.
- **Рисовка остальных:** [общий prompt](../../art/explorations/ilyusha/2026-11-02-selected-04/STYLE.prompt.txt), индивидуальные лица/костюмы/палитры сохранять. Переносить принятый mesh-подход после нового героя.
- **Очистка:** прежние концепты и описания удалить после просмотра/выбора владельца; пока сохраняются. Другие CHARACTER-02…06 остаются самостоятельными открытыми срезами.
