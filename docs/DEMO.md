# ШКЯ: Новосибирск — техническое задание демо «За хлебом»

**Версия:** 1.0 · **Дата:** 27 октября 2026 · **Движок:** Godot 4.x · **Платформа:** Windows / Linux (ПК) · **Исполнитель:** один разработчик.

## 1. Результат

Сделать вертикальный срез трёхмерной аркадной игры с видом от третьего лица, по ощущениям управления вдохновлённой *The Simpsons: Hit & Run*. Герой и второстепенные персонажи выглядят как двумерные персонажи ШКЯ, встроенные в трёхмерный Новосибирск. Игрок завершает **один квест «За хлебом»** за ориентировочно 5–8 минут.

**Готовность демо:** из главного меню запускается цельная играбельная миссия; игрок без подсказок разработчика берёт её, едет за покупкой, возвращается и получает экран выполнения. Все состояния корректно работают после повторного запуска сцены.

## 2. Неприкосновенные художественные требования

- **Локация — Новосибирск**, а не абстрактный город: узнаваемые сибирские панельные дома, дворы, гаражи, вывески на русском, старые «Жигули», киоск «ХЛЕБ». Достоверность достигается характером среды, точная GIS-копия города не нужна.
- **Снег оставляем.** Зима, серые стены, чёрные грязные колеи, рыхлые сугробы, мокрый снег, затоптанные тропинки, низкая контрастность фасадов.
- **Освещение:** тёплые жёлтые уличные фонари, подъездные лампы и окна. Прохладный общий свет улицы, контрастные освещённые зоны интерактивных объектов.
- **Илюша:** настоящее узнаваемое лицо ШКЯ — большая розовая голова, загнутый вверх нос, жёлтый завиток волос. В отличие от летнего оригинального костюма здесь он одет по погоде: **ярко-лаймовый стёганый зимний пуховик с белым воротником, тёмно-зелёные длинные утеплённые брюки, тёмные зимние ботинки**. Капюшон опущен, волосы видны. Костюм одинаков во всех сценах.
- **Бабка:** оригинальные черты ШКЯ — огромная светлая голова, оливково-зелёный головной убор с белой кромкой, длинное зелёное платье с белым воротником. Не заменять образом «обычной мультяшной бабушки».
- **У Илюши всегда пустые руки.** Никаких батонов, пакетов, ключей и другого реквизита в руках. Хлеб после покупки — **логический предмет инвентаря**, отображаемый лишь пиктограммой HUD / состоянием квеста. Передача хлеба Бабке происходит по кнопке взаимодействия без анимации физического предмета.
- Персонажи рисуются с характерным жирным чёрным контуром и плоской заливкой на фоне объёмного, относительно реалистичного грязного города. Важно визуальное выделение Илюши на нейтральном окружении.

## 3. Границы MVP

| Входит | Не входит |
| --- | --- |
| Один непрерывный квартал: двор, короткий путь по двум улицам, хлебный киоск | Весь Новосибирск, открытый мир, метро, интерьеры квартир |
| Илюша как единственный игровой герой | Переключение персонажей, кастомизация, прохожие с развитым ИИ |
| Бабка и продавщица — две диалоговые NPC | Очередь, дополнительные квесты, случайные сюжетные события |
| Одна управляемая белая Lada, вход и выход по `E` | Гараж, тюнинг, автопарк, полиция, система розыска |
| Аркадная езда, ходьба, камера, простой коллизионный мир | Реалистичная физика подвески, сложное повреждение кузова |
| Одна миссия с жёлтыми `!` и `?`, минимальным HUD и указателем маршрута | Полноценное RPG-дерево квестов, крафт, оружие |
| Условный инвентарь `has_bread: bool` | 3D-модель батона в руках, рюкзак, физика предметов |
| Экран завершения `+50 опыта` | Прогрессия персонажа и магазин за опыт |

**Размер блок-аута:** ориентир 200 × 250 м, компактный и визуально убедительный. Минимум контента; расстояние поездки должно ощущаться как поездка, но не утомлять.

## 5. Диалоги и квестовый интерфейс

**Бабка, выдача:** «Илюша, сходи за хлебом в киоск». Кнопки: «ПРИНЯТЬ», «ОТКАЗАТЬСЯ».

**Продавщица:** «Батон? 35 рублей». Кнопки: «КУПИТЬ ХЛЕБ», «УЙТИ». Покупку разрешить один раз, если активен квест и хватает условной валюты. Для демо у Илюши при старте заведомо хватает денег; отдельный UI денег необязателен.

**Бабка, завершение:** «Спасибо, Илюша». По нажатию «Сдать задание» убрать `has_bread`, показать завершение и награду. При повторном разговоре не начислять опыт ещё раз.

**Визуальные маркеры:**

- `!` — можно **получить** задание; виден до принятия.
- `?` — можно **сдать** задание; виден только после покупки и возврата.
- Жёлтый ромб — направление к текущей цели поездки/покупки.
- Слева сверху — название и текущая задача; снизу слева — компактная мини-карта; справа на поездке — скорость.

## 6. Переходы состояний

```text
NOT_STARTED
  └─ E у Бабки → OFFERED
      ├─ ОТКАЗАТЬСЯ → NOT_STARTED
      └─ ПРИНЯТЬ → GO_TO_CAR
          └─ войти в машину → DRIVE_TO_KIOSK
              └─ прибыть в зону киоска → BUY_BREAD
                  └─ КУПИТЬ ХЛЕБ → RETURN_HOME  [has_bread = true]
                      └─ E у Бабки → COMPLETE     [has_bread = false, +50 XP]
```

Передвижение, выход из машины и повторный вход разрешены без нарушения логики. Если игрок приехал к киоску без получения квеста, покупать квестовый хлеб нельзя. До покупки над Бабкой не появляется `?`. Сдача без `has_bread` запрещена. Состояние `COMPLETE` необратимо в рамках сессии. Перезапуск из меню начинает миссию с `NOT_STARTED`.

## 7. Рекомендуемая реализация в Godot

```text
DemoWorld.tscn (Node3D)
├── LevelGeometry (Node3D)        # Двор, 2 улицы, киоск, коллизии
├── LightingAndWeather            # Жёлтые светильники, мокрый снег, лёгкие частицы
├── Ilyusha (CharacterBody3D)     # Ходьба + анимированный SHKYA-спрайт / плоская модель
├── Car (CharacterBody3D)         # Псевдофизика аркадной езды
├── Babka (Node3D + Area3D)       # ! / ? + два диалога
├── Vendor (Node3D + Area3D)      # Один диалог «Купить хлеб»
├── KioskZone (Area3D)            # Прибытие
├── CameraRig (SpringArm3D)       # Отдельные позиции пешком / за авто
├── MissionDirector (Node)        # FSM, проверки переходов, has_bread
└── GameHUD (CanvasLayer)         # Квест, подсказки E, мини-карта, маркеры, финал
```

**Управление:** `WASD` — ходьба/руление; мышь — камера пешком; `E` — взаимодействие, вход/выход из машины; `Space` — ручник в машине; `Esc` — пауза/перезапуск. Камера следит за Илюшей и меняет дистанцию после посадки в машину.

**Движение персонажа:** `CharacterBody3D` с управлением относительно камеры. Для персонажей допустим `AnimatedSprite3D` с несколькими ракурсами (или очень простая 3D-форма с плоскими текстурами); изображение и жёлтая причёска должны быть узнаваемы даже со спины.

**Автомобиль:** начать с аркадного `CharacterBody3D`: ускорение, торможение, скорость, зависимый от скорости угол поворота, слабый контролируемый занос на мокрой дороге. Не строить собственный физический движок и систему подвески до первого проходимого прототипа.

**Из Three.js-референса Hit & Run:** использовать идеи camera-relative движения, chase camera, разделения состояния on-foot/in-car и data-driven этапов задания; реализовать их заново средствами Godot. Не переносить чужие модели, звуки, текстуры, сценарии и интерфейс *The Simpsons*.

**Квестовый предмет:** `has_bread: bool`, без инвентарной UI-панели. На этапе покупки выставить флаг и на 2 секунды показать «ХЛЕБ +1» в HUD. Никаких `RigidBody3D`, подбора с пола, крепления батона к скелету героя или анимации передачи. Сдача — один переход FSM и панель благодарности.

## 8. План производства и контроль качества

| Этап | Результат | Ориентир для одиночной работы |
| --- | --- | --- |
| 1. Greybox | Двор, дороги, киоск, персонаж, камера, зоны | 1–2 недели |
| 2. Вождение | «Лада», вход/выход, управление, коллизии | 1–2 недели |
| 3. Квест | Бабка, продавщица, FSM, `!` / `?`, покупка в логический инвентарь, финал | 1–2 недели |
| 4. Визуальный проход | ШКЯ-персонажи, зимние модели, грязный снег, ламповое освещение, HUD | 2–4 недели |
| 5. Полировка | Тестирование, звук, управление, устранение застреваний, сборка | 1–2 недели |

Это **оценки трудозатрат, не обещание сроков**; часть этапов можно вести параллельно.

### Приёмочные сценарии

1. Полный проход от кадра 01 до кадра 10 без перезапуска, зависаний и ручных команд от разработчика.
2. Жёлтый `!` есть только до принятия, жёлтый `?` — только когда хлеб куплен и квест готов к сдаче.
3. Покупка увеличивает логический инвентарь ровно на 1; ни в одной сцене у Илюши не появляется физический батон или пакет.
4. Персонаж всю игру носит **одинаковый зимний костюм**, в том числе при входе/выходе из машины. Сохраняется узнаваемое лицо ШКЯ.
5. Игрок не может потерять возможность пройти миссию из-за неудачной парковки: автомобиль можно вернуть в доступное положение кнопкой «Сбросить автомобиль» через меню паузы.
6. Повторное нажатие `E` у Бабки не даёт повторной награды; покупка недоступна после её завершения.
7. Мини-карта и маркеры помогают найти обе точки без чтения дополнительных инструкций.
8. Целевой технический ориентир — плавный игровой процесс на обычном игровом ПК; измерить реальные FPS на выбранной тестовой конфигурации, не полагаться на концепт-арты.
