# Город Н

Демо-квест «За хлебом» на Godot в трёхмерном зимнем городе Н. (прототип — Новосибирск). По MSG-0219 временно возвращается прежний 2D-Илюша; рост и цели движения — в DECISIONS. Подбор/переделка 3D и поручение о Гомере остаются отложенными. Оптимизация FPS и света продолжается; после смены backend замеры привязывать к новому срезу. Рост героя фиксирован, окружение и транспорт согласуются с реальными габаритами. *The Simpsons: Hit & Run* — основной референс игрового мира и механик; художественный переход сохраняет существующий геймплей.

Godot 4.7.2, GDScript, Forward+, 1920×1080. `make run` — игра, `make test` и `make test-headless` — проверки без окна; графические наборы явно пропускаются. `make test-native` — только по отдельному явному разрешению владельца (список — Makefile). Локальная Godot.app — в `tools/local/` вне Git. Целевая платформа — этот Mac.

## Процесс

- Исходные просьбы владельца сохранены в [docs/requests/OWNER_MESSAGES.md](docs/requests/OWNER_MESSAGES.md), данные — в `docs/requests/owner_messages.json`. После перезапуска сверять связанные поручения с backlog; новые содержательные сообщения сначала добавлять дословно в архив, затем связывать с ID существующей или новой задачи. Замечание без связи остаётся неразобранным до постановки; исходный текст не удалять и после переноса в задачу. Архив не заменяет DECISIONS и не содержит живых статусов.
- Очередь, зависимости и единственный живой статус — [docs/workflow/backlog.md](docs/workflow/backlog.md); правила и контракты — [docs/workflow/README.md](docs/workflow/README.md); карточки открытых задач — `docs/workflow/tasks/` (закрытые удаляются). Не заводить дубли канона, отдельные progress и отчёты приёмки.
- Логи проверок — `builds/checks/<ID>/`, кадры — `builds/screenshots/<ID>/`; `builds/` вне Git. Съёмщики кадров — `tools/capture/`.
- Технический PASS не заменяет ручной проход: проверка каркаса — не готовность миссии.
- Обычные автоматические проверки запускать в фоне без окна и слышимого звука (`make test-headless` или адресно с `--headless`). По разрешению владельца от 03.11 (MSG-0189, DECISIONS → «Фоновые проверки») игру и необходимые графические замеры можно запускать с видимым окном без повторного согласования. Пропуски графических проверок явно указывать, не считать их PASS. Служебные скрипты запускать через `tools/run.command` или `tools/godot.sh`: общий launcher по умолчанию принудительно включает headless/Dummy. Прямой вызов Godot.app для обхода защиты запрещён. Для необходимой графической проверки задавать `GODOT_VISIBLE_CHECKS=1` только на её команду; не сохранять его в окружении сессии. Разрешение на игру и графику не добавляет отдельных звуковых проверок.
- [Карта арены](docs/maps/arena.png) и её SVG генерируются из данных игры: `make map`. При изменении геометрии, проходов, маршрутов или ориентиров обновляй карту перед коммитом; `make run`, `make editor`, `make test`, `make capture` и `make fps` обновляют её автоматически. Координаты править только в коде. На карте и в сообщениях владельцу использовать вывески и понятные ориентиры, служебные ID оставлять для кода.

## Режим работы

- Главное художественное правило — «Тёплое чувство в холодном городе» в DECISIONS; там указан актуальный набор музыкальных ориентиров общего впечатления игры.
- Брать задачи из backlog по критическому пути и работать без остановок до блокера: решение владельца, необратимое или внешнее действие, запрет среды. На запрос отчёта — короткий отчёт и продолжение в том же ходе.
- Независимые задачи — параллельно силами субагентов, проверяя свободную память перед запуском.
- Законченную проверенную часть — атомарным коммитом с ID задачи. Пуш — только по отдельному поручению.

Демо принимается по строке «Готовность демо» в DECISIONS: каждый эксперт ≥8/10 и стабильные 120 FPS везде. Цель оптимизации после этого продолжает расти до 200.

### Экономия контекста и моделей

- Новому агенту по умолчанию `fork_turns="none"`: цель, принадлежащие ему файлы, нужные контракты, пути доказательств и критерий готовности. Всю историю передавать только при обоснованной необходимости.
- Выбирать модель явно: `gpt-6-luna`/`low` — извлечение данных и простые правки; `gpt-6.1-sol`/`medium` — код и обычная проверка; Sol/`high` — сложная диагностика FPS, света и регрессий. Повышать сложность модели по конкретной неудаче; `xhigh`/`max` — при доказанной необходимости.
- В DECISIONS и backlog сначала искать нужную тему/ID через `rg -n`, затем читать относящиеся строки и зависимости; ссылки не требуют загрузки всех документов. Обязательные правила и проверку результата сохранять.
- Переиспользовать результаты экспертов; повторять замер при изменении входов или новой неопределённости. Поручения ограничивать одним результатом, ответы — новыми фактами и путями логов. Завершённые агенты не требуют опроса; пауза подбора 3D сохраняется.

Постоянные роли по MSG-0216 (создавать только нужных для текущей задачи):

| Роль / имя агента | Модель / reasoning | Ответственность |
|---|---|---|

| Свет `light_expert` | `gpt-6.1-sol` / `high` | Свет, тени, материалы и атмосфера; качество вместе с бюджетом кадра |

| Независимая проверка `fps_measurement_qa` | `gpt-6.1-sol` / `medium` | Регрессии, достоверность FPS, приёмка чужой правки; сложный разбор — `high` |
